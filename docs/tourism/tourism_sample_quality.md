# 관광 fallback 샘플 품질 QA

마지막 갱신: 2026-05-15

`data/raw/tourism_accessible/`는 live TourAPI 호출을 줄이고 시연 안정성을 확보하기 위한 fallback/색인 후보 데이터다. 추가 수집 전에 먼저 현재 샘플의 품질과 분포를 확인한다.

## 실행 방법

```bash
.venv/bin/python scripts/audit_tourism_samples.py
```

기본 리포트는 아래 위치에 생성된다.

```text
data/generated/tour_api/tourism_sample_audit.md
```

`data/generated/` 아래 산출물은 로컬 분석 결과이므로 커밋하지 않는다. 문서화가 필요한 결론만 `docs/tourism/tourism_data_collection_plan.md` 또는 `docs/project/progress_overview.md`에 반영한다.

## 확인 기준

- Markdown 파일 수와 파싱 성공 수가 일치하는지 본다.
- 중복 `콘텐츠ID`가 많은지 확인한다. 중복은 같은 카드가 지역 prefix만 다르게 들어왔을 가능성이 있다.
- 주소, 출처 URL, 추천근거 같은 필수 카드 정보가 비어 있는지 확인한다.
- 지역별 파일 수가 MVP 테스트 지역과 주요 광역권을 충분히 덮는지 본다.
- 접근성 태그가 휠체어에만 치우치지 않고 주차, 화장실, 보조견, 유모차 등도 확인 가능한지 본다.
- 가족 태그가 부족하면 가족/유모차 질문의 답변 품질을 별도로 점검한다.

## 다음 판단

- 특정 지역 파일 수가 부족하면 `scripts/fetch_accessible_tourism_samples.py --regions ... --max-api-calls 100`처럼 좁게 보강한다.
- 품질 문제 없이 지역 커버리지가 충분하면 추가 수집보다 20문항 eval 실행을 우선한다.
- 중복 콘텐츠ID가 많으면 수집 스크립트의 중복 회피 결과와 live cache 분리 정책을 다시 확인한다.
- 중복 콘텐츠ID를 CI/QA 실패 조건으로 보고 싶으면 아래처럼 실행한다.

```bash
.venv/bin/python scripts/audit_tourism_samples.py --fail-on-duplicates
```

## 2026-05-15 현재 감사 결과

중복 정리와 시군구 fallback 확장 수집 후 `scripts/audit_tourism_samples.py --fail-on-duplicates` 실행 결과:

- Markdown 파일 808개 중 808개 파싱 성공
- 파싱 실패 0개
- 필수 필드 누락 0개
- 주소 확인 필요 0개
- 출처 URL 확인 필요 0개
- 중복 콘텐츠ID 0개

광역권 fallback 정리 전 중복은 모두 `강릉_*` 파일과 `강원_*` 파일에 같은 콘텐츠ID가 함께 존재하는 형태였다. 즉 같은 장소가 강릉 특화 샘플과 강원 광역 샘플에 중복 편입된 상태였다.

원인은 다음 두 가지가 겹친 것으로 본다.

1. 수집 프리셋에 도 단위 `강원`과 시 단위 `강릉`이 모두 포함되어 있다. TourAPI에서 강원 광역 결과에 강릉 장소가 포함될 수 있으므로, 두 지역을 모두 수집하면 같은 콘텐츠ID가 나올 수 있다.
2. 현재의 콘텐츠ID 중복 회피 로직이 들어가기 전 또는 중복을 실패로 보지 않던 시점에 `강원_*`와 `강릉_*` 파일이 각각 생성됐다. 이후에는 파일이 이미 존재하므로 감사에서 중복으로 드러난다.

재발 방지책:

- 수집 스크립트는 실행 시작 시 `data/raw/tourism_accessible/`와 `data/generated/tour_api/live_markdown/`의 기존 Markdown을 모두 읽어 콘텐츠ID 인덱스를 만든다.
- 이미 존재하는 콘텐츠ID는 상세 API 호출 전에 건너뛴다. 즉 같은 장소가 다른 지역 프리셋에서 다시 발견되어도 새 Markdown을 만들지 않는다.
- 기존 샘플에 이미 중복 콘텐츠ID가 있으면 수집 시작 시 경고를 출력한다.
- 감사 스크립트는 `--fail-on-duplicates` 옵션으로 중복을 실패 조건으로 만들 수 있다.
- 다음 추가 수집 전에는 감사 스크립트를 먼저 실행하고, 중복이 새로 늘어났는지 확인한다.

처리 결과:

- 더 구체적인 `강릉_*` 파일을 canonical fallback으로 보존했다.
- 중복 `강원_*` 파일 16개를 제거했다.
- `scripts/rebuild_index.py`로 Chroma를 재색인했다.
- 시군구 fallback 이어받기 수집 후 재색인 결과는 전체 raw 기준 809개 문서/816개 청크다.

현재 응답 단계에서도 콘텐츠ID 기준 카드 중복 제거를 유지한다.

지역 분포는 광역권 fallback 정리 후 대부분 20개였고, 이후 시군구 fallback 확장으로 전국 시군구 대부분이 3장 이상 확보됐다. 2026-05-16 이어받기 수집 기준 TourAPI 지역 코드 234개 중 228개 시군구가 3장 이상 확보됐다. 0장 지역은 청원군, 마산시, 진해시, 남제주군, 북제주군이고, 3장 미만 지역은 계룡시 1장이다. 0장 5개 지역은 폐지/통합 지명으로 보고 사용자 질문에서는 현재 행정구역명으로 안내한다. 매핑은 청원군 -> 청주시, 마산시 -> 창원시, 진해시 -> 창원시 진해구 안내/TourAPI 창원시 기준, 남제주군 -> 서귀포시, 북제주군 -> 제주시다. 계룡시는 실제 저커버리지 지역으로 별도 보강 대상이다. 전국 실사용 지역 250개 기준에는 행정시/일반구 등 추가 대상이 포함될 수 있으므로 별도 대상 목록 확장이 필요하다. 제거한 `강원_*` 중복 파일은 모두 같은 콘텐츠ID의 `강릉_*` 파일로 보존되어 있고 주소에는 `강원특별자치도 강릉시`가 남아 있다. 강원 광역 질문의 실제 품질은 확장 eval 또는 별도 강원 질문으로 확인한다. curated 샘플은 `seoul` 3개, `gangneung` 2개, `busan` 1개가 남아 있다.

접근성 태그 상위 항목은 대중교통 503개, 휠체어 접근 477개, 장애인 주차 402개, 장애인 화장실 360개 순서다. 가족 태그는 가족 친화 131개, 영유아 동반 81개, 수유실 71개, 유모차 대여 61개, 유아용 의자 52개로 휠체어 조건보다 적으므로 가족/유모차 질문은 확장 eval에서 별도 확인한다.
