# 선택형 무장애 관광 추천 앱 기획안

## 목적

현재 자연어 챗봇 방식과 별도로, 사용자가 문장을 입력하지 않고 선택지를 따라가며 관광 조건을 구성하는 앱 방식을 검토한다. 목표는 시연 안정성, 결과 재현성, 낮은 입력 부담을 확보하면서도 필요할 때만 자연어 심층 해석을 보조 기능으로 제공하는 것이다.

## 기본 방향

이 앱은 자유 대화를 기본 입력으로 삼지 않는다. 사용자는 지역, 관광 유형, 동반자, 접근성 조건, 제외 조건, 선호도를 순서대로 선택한다. 선택값은 바로 내부 검색 조건으로 변환되므로 오타, 띄어쓰기, 반어, 우회 표현 해석 문제를 크게 줄일 수 있다.

## 사용자 흐름

1. 지역 선택  
   광역시/도 → 시군구 순서로 선택한다. 애매한 지역명 문제를 UI에서 제거한다.

2. 관광 유형 선택  
   관광지, 문화시설, 자연/공원, 체험, 음식/카페 제외 등 기본 카테고리를 고른다.

3. 동반 상황 선택  
   혼자, 가족, 영유아 동반, 어르신 동반, 휠체어 이용, 유모차 이용 등을 선택한다.

4. 접근성 조건 선택  
   장애인 화장실, 장애인 주차, 경사로, 엘리베이터, 점자 안내, 음성 안내, 수어 안내, 자막 자료, 수유실, 기저귀 교환대 등을 고른다.

5. 조건 강도 선택  
   필수 조건과 있으면 좋은 조건을 분리한다.

6. 제외 조건 선택  
   시장 제외, 음식점 제외, 숙박 제외, 야외 코스 제외, 오래 걷는 코스 제외처럼 추천에서 빼고 싶은 항목을 선택한다.

7. 추천 결과 확인  
   카드 형태로 결과를 보여주고, 부족할 경우 조건 완화 또는 지역 확장 버튼을 제공한다.

## 내부 데이터 구조

선택값은 다음과 같은 구조로 변환한다.

```json
{
  "region": "부산",
  "sigungu": "중구",
  "category": ["관광지", "문화시설"],
  "required_conditions": ["wheelchair", "elevator"],
  "preferred_conditions": ["quiet", "indoor"],
  "excluded_categories": ["market"],
  "companion_context": ["family", "stroller"]
}
```

이 구조를 기준으로 TourAPI, 무장애 상세 정보, fallback 카드, 추천 정렬을 실행한다.

## 자연어 입력의 위치

자연어 입력은 기본 경로가 아니라 선택 기능으로 둔다. 예를 들어 사용자가 "엄마가 오래 못 걸어서 많이 안 움직이는 곳이면 좋겠어"처럼 선택지로 표현하기 어려운 내용을 입력하면, 별도 "자연어로 조건 추가" 모드에서 처리한다.

이 모드는 빠른 응답보다 해석 품질을 우선한다. 필요하면 LLM thinking 또는 느린 문맥 해석을 사용해 사용자의 문장을 구조화된 조건으로 변환하고, 변환 결과를 바로 적용하지 않고 사용자에게 확인시킨다.

예:

```text
입력: 엄마가 오래 못 걸어서 많이 안 움직이는 곳이면 좋겠어
해석 결과:
- 동반 상황: 어르신/보행 약자
- 선호 조건: 짧은 동선, 앉아 쉴 곳
- 필수 조건: 없음
```

사용자는 이 해석 결과를 확인한 뒤 적용한다.

## 장점

- 입력 오류와 문맥 오해를 크게 줄일 수 있다.
- 같은 선택값은 같은 추천 조건으로 처리되므로 재현성이 높다.
- 공모전 시연에서 실패 확률이 낮다.
- 조건 강도, 제외 조건, 지역 확장을 UI에서 명확히 제어할 수 있다.
- 자연어 NLU/Transformer는 필수 런타임이 아니라 보조 기능으로 둘 수 있다.

## 한계

- 일반적인 챗봇처럼 자유롭게 말하는 경험은 약해진다.
- 선택지가 많아지면 사용자가 피로할 수 있다.
- 사용자의 복합 사정을 모두 버튼으로 표현하기 어렵다.
- 자연어 보조 모드를 넣을 경우 응답 시간이 길어질 수 있다.

## 현재 챗봇 방식과의 관계

이 방식은 현재 자연어 챗봇을 대체한다기보다 별도 앱 후보로 본다. 자연어 챗봇은 "사용자가 문장으로 말했을 때 얼마나 잘 해석할 수 있는가"를 보여주는 방향이고, 선택형 앱은 "실제 시연과 운영에서 얼마나 안정적으로 추천 조건을 받을 수 있는가"를 보여주는 방향이다.

따라서 두 방식은 다음처럼 역할을 나눌 수 있다.

| 방식 | 역할 |
|---|---|
| 선택형 설문 앱 | 안정적인 기본 추천 경로 |
| 자연어 챗봇 | 자유 입력 실험 및 고급 입력 경로 |
| LLM thinking 보조 | 복잡한 문장을 구조화 조건으로 변환하는 느린 해석 모드 |

## 1차 구현 범위

- 지역/시군구 선택
- 관광 유형 선택
- 접근성 조건 다중 선택
- 필수/선호 조건 분리
- 제외 조건 선택
- 추천 카드 출력
- 조건 완화/지역 확장 버튼
- 자연어 조건 추가 모드의 해석 결과 확인 화면

## 판정

시연 안정성과 사용자 입력 통제를 우선하면 선택형 설문 앱 방식이 유리하다. 다만 프로젝트의 ML/NLU 설명력을 유지하려면 자연어 해석 기능을 완전히 제거하지 말고, 느리지만 검증 가능한 보조 모드로 두는 것이 적절하다.
