# 무장애 관광 챗봇 추가 기능 보강안

## 목적

현재 기본 기능은 자연어 질문을 해석해 무장애 관광 카드를 추천하는 것이다. 이 문서는 기본 추천 기능 위에 추가하면 서비스 완성도와 사용자 편의성을 높일 수 있는 기능을 정리한다.

## 우선 적용 후보

### 1. 조건 확인형 질문 UI

사용자 표현이 애매하면 바로 추천하지 않고 선택 버튼으로 확인한다.

- 휠체어 접근
- 입구/동선 접근로
- 어르신 이동 부담 적은 곳
- 장애인 화장실
- 대중교통 접근

현재 백엔드에는 `ambiguous_conditions`와 `clarification` 응답 정책이 있으므로, 프론트엔드에서 이를 버튼 선택 흐름으로 연결하면 된다.

2026-05-18 1차 반영:

- `/tourism-ui/`에서 `lookup_mode=clarification` 응답을 지역 확인과 조건 확인으로 구분한다.
- 조건 확인일 때는 `조건 확인 필요` 배너와 선택형 버튼을 보여준다.
- 버튼 라벨은 `휠체어 접근`, `입구/동선 접근로`, `어르신 이동 부담 적은 곳`, `장애인 화장실`, `대중교통 접근`처럼 짧은 기준명으로 표시한다.
- 버튼을 누르면 백엔드가 생성한 원래 후속 질문 문장을 그대로 보내므로 세션 맥락과 지역 정보는 유지된다.

적용 예시:

| 예시 질문 | 화면 동작 | 기대 흐름 |
| --- | --- | --- |
| `중구에서 접근 좋은 곳 추천해줘` | `중구`가 여러 지역에 있을 수 있으므로 지역 선택 버튼을 먼저 보여준다. | 사용자가 `서울 중구`, `부산 중구`, `인천 중구` 등 후보 중 하나를 누르면 원래 질문 맥락을 유지한 채 다시 조회한다. |
| `서울에서 어르신이랑 이동 편한 관광지 추천해줘` | `어르신 이동 부담 적은 곳`, `휠체어 접근`, `대중교통 접근` 같은 조건 확인 버튼을 보여준다. | 사용자가 원하는 접근성 기준을 고른 뒤 추천 카드 조회로 넘어간다. |
| `강남구에서 접근성 좋은 실내 관광지` | `접근성` 표현이 넓으면 조건 확인 배너와 선택 버튼을 표시한다. | 모델이 임의로 단정하지 않고 사용자가 기준을 확정한다. |

### 2. 추천 카드별 근거 강조

추천 카드마다 왜 해당 카드가 나왔는지 조건별로 보여준다.

- 휠체어: 출입통로, 경사로, 무단차, 휠체어 접근
- 화장실: 장애인 화장실 확인
- 주차: 장애인 주차구역 또는 주차장 정보
- 대중교통: 정류장/역 접근, 출입구 접근 정보
- 고령자: 휠체어 접근, 경사로, 화장실, 대중교통 같은 이동 편의 근거

현재 답변 문장에는 근거가 포함되지만, 카드 UI에서 아이콘/태그/짧은 근거 줄로 분리하면 사용자가 더 빨리 판단할 수 있다.

2026-05-18 1차 반영:

- 카드 본문에 조건별 근거 칩을 추가했다.
- 휠체어, 동선, 화장실, 주차, 승강, 수어/자막, 점자/촉지, 유아 편의 근거를 카드 원문 필드와 접근성 요약에서 추출한다.
- 상세 정보는 기존처럼 펼쳐 볼 수 있고, 근거 칩은 빠른 스캔용 요약으로만 사용한다.

적용 예시:

| 예시 질문 | 카드에서 강조되는 근거 | 기대 흐름 |
| --- | --- | --- |
| `서울 강남구에서 휠체어 관광지 추천해줘` | `휠체어`, `동선`, `화장실`, `주차` 근거 칩을 우선 표시한다. | 사용자는 답변 문장을 길게 읽기 전에 카드별 핵심 조건을 비교한다. |
| `부산에서 유아차로 가기 좋은 곳 추천해줘` | `유아`, `동선`, `승강`, `화장실` 관련 근거를 우선 보여준다. | 유모차/가족 조건에 맞는 근거가 있는지 카드에서 바로 확인한다. |
| `제주에서 점자 안내 있는 곳 찾아줘` | `점자/촉지` 근거가 있으면 별도 칩으로 표시한다. | 데이터가 부족하면 시설 부재로 단정하지 않고 확인 필요 상태를 유지한다. |

### 3. 데이터 부족 안내와 조건 완화

무장애 데이터가 부족한 지역에서는 실패 문장만 보여주지 않고 다음 행동을 제안한다.

- 해당 지역에는 확인된 카드가 적다는 안내
- 같은 시·도 범위로 넓히기
- 조건 일부 완화하기
- 필수 조건과 선호 조건을 나누기

예시:

```text
강릉시 안에서 확인된 수어/자막 카드가 부족합니다.
조건을 유지하고 강원특별자치도 범위로 넓혀볼까요?
```

2026-05-18 1차 반영:

- 카드가 0장인 응답의 `suggested_messages`를 회복 액션 버튼으로 표시한다.
- 같은 시·도 확장은 `같은 시·도까지 넓히기`, 조건 완화는 `조건 완화하기`처럼 짧은 버튼명으로 보여준다.
- 백엔드의 빈 결과 제안은 같은 조건 재검색, 같은 시·도 확장, 무장애 기준 조건 완화 후보를 각각 한 번씩 생성한다.

적용 예시:

| 예시 질문 | 화면 동작 | 기대 흐름 |
| --- | --- | --- |
| `제주시 안에서 수어 안내와 점자 안내가 모두 있는 곳만 보여줘` | 추천 카드가 없으면 0건 상태와 함께 회복 버튼을 보여준다. | `이 조건으로 다시 찾기`, `같은 시·도까지 넓히기`, `조건 완화하기`를 중복 없이 선택하게 한다. |
| `강릉시에서 점자 안내 필수인 실내 관광지 추천해줘` | 지역/조건 조합으로 카드가 부족하면 부족 이유와 다음 행동을 분리해 표시한다. | 점자 조건을 완화하거나 강원특별자치도 범위로 넓히는 흐름을 제안한다. |
| `성남시에서 수어 자막 둘 다 되는 실내식당` | 무장애 관광 카드가 부족하거나 장소 유형이 맞지 않으면 일반 관광 전체가 아님을 안내한다. | 조건을 완화하거나 무장애 관광 연관 장소 중심으로 다시 묻도록 유도한다. |

### 4. 지역 확장 컨트롤

자동으로 지역을 넓히지 않고 사용자가 직접 선택하게 한다.

- 현재 시군구만
- 같은 시·도까지
- 전국 무장애 후보 중 조건 우선

`근처`, `주변`, `가까운` 같은 표현은 사용자가 보통 입력 지역 자체를 기대할 수 있으므로 자동 광역 확장 신호로 쓰지 않는다. 확장은 `서울 전체로 넓혀줘`, `범위 넓혀줘`처럼 명시된 경우 또는 UI 버튼 선택으로 처리한다.

2026-05-18 1차 반영:

- 시군구 안에서 반환 카드가 적을 때 자동으로 광역 카드를 섞지 않고, 같은 시·도 확장 버튼을 제안한다.
- 사용자가 버튼을 누르거나 `서울 전체로 넓혀줘`처럼 명시한 경우에만 확장 조회 문장을 보낸다.
- 프론트엔드는 확장 제안을 `같은 시·도까지 넓혀 보기`로 짧게 표시한다.

적용 예시:

| 예시 질문 | 화면 동작 | 기대 흐름 |
| --- | --- | --- |
| `서울 강남구 근처에서 휠체어 관광지 추천해줘` | `근처`가 있어도 우선 강남구 후보를 먼저 보여준다. | 강남구 후보가 부족할 때만 `같은 시·도까지 넓혀 보기` 버튼을 제안한다. |
| `서울 강남구에서 휠체어 관광지 추천해줘. 부족하면 서울 전체로 넓혀줘` | 사용자가 조건부 확장을 명시했으므로 강남구 후보가 기본 표시 수보다 부족할 때만 서울 범위 확장 후보를 섞는다. | 부족하지 않으면 강남구 후보만 먼저 보여주고, 확장했다면 답변 문구에 확장 여부를 명확히 표시한다. |
| `강남구 후보 더 없어? 서울 전체로 넓혀줘` | 후속 질문으로 확장 의도가 명확하므로 같은 시·도 범위로 다시 조회한다. | 기존 세션 맥락의 접근성 조건을 유지한 채 확장한다. |

### 5. 옵션형 추천 모드

자연어 입력이 어려운 사용자를 위해 설문식 추천 흐름을 제공한다.

1. 지역 선택
2. 장소 유형 선택
3. 동행 상황 선택
4. 접근성 조건 선택
5. 필수/선호 조건 분리
6. 추천 결과 확인

자세한 별도 기획은 `docs/tourism/option_flow_app_concept.md`에 정리되어 있다.

## 중기 적용 후보

### 방문 전 체크리스트

추천 결과 하단에 방문 전 확인 항목을 제공한다.

- 운영시간 확인
- 장애인 화장실 위치 확인
- 휠체어 대여 가능 여부 확인
- 주차장 위치 확인
- 전화 확인 권장

무장애 관광 정보는 현장 상황이 바뀔 수 있으므로, 체크리스트는 실제 사용성을 높인다.

### 추천 결과 저장/공유

사용자가 추천 결과를 다시 볼 수 있도록 한다.

- 추천 저장
- 선택한 카드만 모아 보기
- 공유 링크 만들기
- 방문 후보 목록 만들기

시연에서는 결과물이 남는 느낌을 줄 수 있고, 실제 서비스에서는 재방문 편의성이 좋아진다.

### 실패 케이스 피드백

카드 또는 답변 하단에 간단한 피드백 버튼을 둔다.

- 조건과 안 맞아요
- 정보가 부족해요
- 운영 정보가 달라요
- 좋은 추천이에요

이 로그는 이후 조건 사전, Transformer 학습셋, 카드 랭킹 보강 데이터로 활용할 수 있다.

### 실시간 확인 버튼

기본 응답은 보유 캐시/샘플/인덱스 기준으로 빠르게 제공하고, 사용자가 원할 때만 최신 확인을 수행한다.

- 최신 정보 더 찾기
- TourAPI 다시 확인
- 전화 확인 필요 표시

현재 live top-up 흐름이 있으므로 UI에서 명확한 액션으로 드러내면 된다.

### 접근성 프로필 저장

사용자가 매번 조건을 말하지 않아도 기본 조건을 저장한다.

- 휠체어 이용
- 유모차 동반
- 청각장애 접근성 필요
- 시각장애 접근성 필요
- 고령자 동행

프로필은 자동 적용하되, 답변에는 “저장된 휠체어 접근 조건을 함께 적용했습니다”처럼 투명하게 표시한다.

## 추천 우선순위

현재 프로젝트에는 다음 순서가 가장 실용적이다.

1. 조건 확인형 질문 UI
2. 카드별 근거 강조
3. 데이터 부족 안내와 조건 완화
4. 지역 확장 컨트롤
5. 옵션형 추천 모드
6. 실패 케이스 피드백

## 판정

추가 기능의 핵심은 모델을 더 복잡하게 만드는 것이 아니라, 사용자가 조건을 명확히 고르고 결과 근거를 쉽게 확인하게 만드는 것이다. 자연어 NLU는 계속 보강하되, 실제 서비스 완성도는 확인 질문, 지역 확장 선택, 카드 근거 시각화, 피드백 루프에서 크게 올라간다.
