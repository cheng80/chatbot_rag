# 전국 시군구 fallback 최소 수집 규모

마지막 갱신: 2026-05-15

## 목적

현재 확보한 fallback은 광역권별 약 20장 수준의 최소 안전망이다.  
이 문서는 나중에 fallback을 **전국 시군구 단위**로 더 촘촘히 만들 경우, 어느 정도 데이터와 API 호출이 필요한지 미리 계산한 규모표다.

추가 API 호출 없이 `data/processed/tour_area_codes.json`의 `area_codes` 기준으로 계산했다.

## 결론

- 전국 공식 시군구 수: **234개**
- 시군구별 3장 fallback: **702장**
- 시군구별 5장 fallback: **1,170장**
- 시군구별 10장 fallback: **2,340장**
- 엔드포인트별 1,000건/일 제한을 고려하면, 전국 시군구별 5장 이상은 하루에 끝내지 않는 것이 안전하다.

## 호출량 계산식

시군구 하나를 수집할 때 대략 다음 호출이 필요하다.

```text
areaBasedList2 1회
detailCommon2 N회
detailWithTour2 N회
```

따라서 시군구별 `N`장 후보를 확인하면:

```text
총 호출 수 = 시군구 수 * (1 + 2N)
```

단, 일일 제한은 전체 합산이 아니라 엔드포인트별로 볼 가능성이 크므로 특히 `detailCommon2`, `detailWithTour2` 호출 수를 따로 봐야 한다.

## 권장 수집 전략

### 1단계: 지금 상태 유지

현재 이미 광역권별 약 20장 수준 fallback을 확보했다.  
당장 6월 10일 전 기본 서비스 완성에는 충분한 안전망이다.

### 2단계: 품질 QA 후 부족한 시군구만 보강

전국 234개 시군구를 무조건 수집하지 않는다.

우선 확인할 것:

- live 결과가 자주 비는 시군구
- 동명이 지역 테스트에 자주 쓰는 `중구`, `남구`, `동구`, `서구`, `북구`
- 사용자 질문 가능성이 높은 서울/부산/인천/제주/강원 주요 시군구
- 음식점/숙박업소가 과하게 섞이는 지역

### 3단계: 정말 전국 시군구 fallback이 필요하면 3장부터

전국 시군구별 3장은 `detailCommon2`와 `detailWithTour2`가 각각 702회라 엔드포인트별 1,000건 안에 들어온다.  
그래도 live UI 테스트, 재시도, timeout을 고려하면 하루에 전부 돌리지 말고 2일 이상으로 나누는 것이 안전하다.

권장 분할:

```text
Day A: 수도권 + 광역시
Day B: 강원/충청/전라/제주
Day C: 경상권 + 실패 지역 재시도
```

### 4단계: 시군구별 5장 이상은 며칠로 분리

시군구별 5장은 `detailCommon2`와 `detailWithTour2`가 각각 1,170회라 엔드포인트별 1,000건을 넘는다.

따라서 최소 2일, 안전하게는 3일 이상으로 나눠야 한다.

## 지금 당장 하지 말 것

- 오늘 추가 수집
- 전국 시군구 5장 이상 일괄 수집
- 외부 터널을 열어 둔 채 live UI 반복 테스트
- 부족 여부를 확인하지 않고 같은 지역 배치 재수집

## 다음에 구현할 수집 옵션

현재 수집 스크립트는 광역 단위 batch에 맞춰져 있다. 시군구 단위 fallback을 하려면 다음 옵션을 추가하는 것이 좋다.

```text
--sigungu-fallback
--cards-per-sigungu 3
--areas '서울,부산,인천'
--max-api-calls 300
--skip-existing
```

이 옵션은 이미 있는 지역 Markdown을 덮어쓰기보다, 없는 시군구만 채우는 방식이어야 한다.
