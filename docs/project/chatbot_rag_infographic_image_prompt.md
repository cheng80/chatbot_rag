# 챗봇 RAG 내부 구조 이미지 생성 프롬프트

아래 프롬프트는 `docs/project/chatbot_rag_internal_process_infographic.html`의 최신 내용을 바탕으로, ChatGPT 이미지 생성이나 다른 이미지 생성 도구에 넣어 새 포스터 이미지를 만들 때 사용한다.

목표는 정확한 운영 명세표가 아니라, 한눈에 흐름이 읽히는 AI 생성형 기술 인포그래픽이다. 다만 너무 추상적인 업무 흐름처럼 보이지 않도록, RAG를 이해하는 데 필요한 핵심 기술명과 대표 수치는 일부 유지한다.

## 최종 프롬프트

첨부한 HTML 파일을 참고해서 세로형 기술 인포그래픽 이미지를 새로 그려줘.

중요:

- HTML을 그대로 렌더링하거나 웹페이지 스크린샷처럼 만들지 마.
- HTML의 사실, 제목, 단계 순서, 핵심 메시지만 추출해서 새 이미지로 재해석해.
- 정보량은 줄이되, 기술 구조도라는 느낌은 유지해.
- 이전 예시처럼 손으로 정리한 기술 해부도 느낌을 참고하되, 깔끔한 AI technical infographic poster 스타일로 만들어줘.
- 작은 글씨를 많이 넣지 말고, 큰 단계명 + 아이콘 + 짧은 설명 중심으로 구성해.

작업 순서:

1. HTML에서 현재 프로젝트 사실만 추출해.
2. 8단계 흐름은 유지하되, 각 단계는 핵심 3~4개의 시각 요소로 압축해.
3. 세부 API명, 내부 벤치마크 숫자, 긴 설명은 이미지에 모두 쓰지 말고 참고 정보로만 사용해.
4. 이미지 안의 텍스트는 제목, 단계명, 핵심 라벨, 짧은 설명, 대표 수치 3개 정도로 제한해.
5. 최종 결과가 기술 문서 표가 아니라 SNS에서 한눈에 읽히는 인포그래픽처럼 보이게 해.

반드시 유지할 큰 내용:

- 제목: `챗봇 RAG 내부 구조`
- 부제: `사용자 질문이 근거 있는 관광 추천 카드로 변환되기까지의 전체 흐름`
- 예시 질문: `서울 강남구에서 휠체어 관광지 추천해줘`
- 핵심 메시지: `먼저 저장 자료를 찾고, 부족할 때만 실시간 공공데이터를 조회하며, 확인된 근거가 없는 접근성 정보는 만들지 않는다.`

전체 흐름:

1. 질문 입력
2. 질문 해석
3. 지역 확정
4. 저장 자료 검색
5. TourAPI 보강
6. 추천 카드 생성
7. 답변 표시
8. 로깅 및 평가

단계별 표시 내용은 아래처럼 간결하게 그려줘. 각 단계는 아이콘 3~4개와 화살표 2~3개 정도만 사용한다.

1. 질문 입력
   - 사용자 질문
   - 입력 검증
   - 대화 흐름 준비
   - 짧은 설명: 질문을 안전하게 정리

2. 질문 해석
   - 지역
   - 접근성 조건
   - 제외/후속 조건
   - 짧은 설명: 추천 조건으로 분해

3. 지역 확정
   - 지역 후보
   - 모호하면 질문
   - 검색 범위 확정
   - 짧은 설명: 엉뚱한 지역을 섞지 않음

4. 저장 자료 검색
   - 캐시
   - 904개 Markdown
   - Chroma + bge-m3
   - top_k=40 후보
   - 짧은 설명: 저장 자료를 먼저 검색

5. TourAPI 보강
   - 후보 부족
   - TourAPI 조회
   - 로컬 저장
   - 짧은 설명: 부족할 때만 실시간 보강

6. 추천 카드 생성
   - 근거 추출
   - 필수 조건 확인
   - 카드 정렬
   - 짧은 설명: 없는 정보는 만들지 않음

7. 답변 표시
   - JSON 응답
   - LLM 보조 선택
   - 카드 표시
   - 출처·주의 문구
   - 짧은 설명: 화면에 추천 카드 전달

8. 로깅 및 평가
   - 이벤트 로그
   - 품질 점검
   - 문서 개선
   - 짧은 설명: 실패 유형과 회귀를 기록

표시해도 되는 핵심 기술명:

- FastAPI
- `/tourism/chat`
- Chroma
- bge-m3
- TourAPI
- JSON
- SuperGemma4

기술명 표시 규칙:

- 위 기술명을 전부 크게 표시할 필요는 없다.
- 본문에는 `Chroma + bge-m3`, `TourAPI`, `JSON`, `LLM 보조` 정도는 보이게 해.
- `SuperGemma4`는 하단 구성 요소 strip 또는 7단계의 작은 보조 라벨로만 작게 넣어.
- `areaBasedList2`, `detailCommon2`, `detailWithTour2` 같은 세부 API명은 이미지에 쓰지 마. 내부 참고로만 둬.

숫자와 시간 표현:

- 오른쪽 상단 요약 박스에는 하나만 크게 써:
  - `저장 자료 직접 응답: 대부분 약 0.3초 안팎`
- 필요하면 작은 참고로 하나만 더 써:
  - `LLM 보조 ON: 더 느려질 수 있음`
- `2ms`, `87ms`, `3.9초` 같은 세부 벤치마크 숫자는 이미지에 넣지 마.
- `top_k=40`, `904개 Markdown`은 4단계 저장 자료 검색이나 하단 참고 박스 중 한 곳에 넣어도 된다.

텍스트 양 제한:

- 전체 이미지 안의 한국어 문장은 24개 이하로 제한해.
- 각 단계 설명은 한 줄, 20자 안팎으로 짧게 써.
- 각 단계의 작은 라벨은 최대 4개만 사용해.
- 오른쪽 `무엇을 하나요?` 박스 대신, 각 단계 오른쪽에 짧은 한 줄 설명을 넣어.
- 시간 badge는 모든 단계에 붙이지 말고, 상단 요약 박스 하나로 통합해.
- 하단 구성 요소는 6~7개 아이콘만 사용하고, 긴 설명은 쓰지 마.
- 참고 사항은 3~4개 이하로 제한해.

권장 레이아웃:

- 상단: 큰 제목 + 부제 + 오른쪽에 짧은 응답 시간 요약 박스
- 그 아래: 예시 질문 말풍선 + 핵심 메시지 callout
- 본문: 8개 가로 섹션을 세로로 쌓되, 각 섹션 높이를 넉넉하게 유지
- 왼쪽: 사용자에서 응답 완료까지 이어지는 세로 화살표
- 각 섹션:
  - 왼쪽에 큰 번호와 단계명
  - 가운데에 아이콘 3~4개와 화살표
  - 오른쪽에 짧은 한 줄 설명 배치
- 하단:
  - `응답 완료` badge
  - 핵심 구성 요소 strip
  - 작은 참고 사항 3개

하단 핵심 구성 요소 strip:

- 프론트엔드
- FastAPI
- 조건 해석
- Chroma
- bge-m3
- TourAPI
- 로그·평가

하단 참고 사항은 아래 중 최대 3개만 선택:

- 운영 검색 폭은 `top_k=40`
- 예비 관광 카드는 `904개 Markdown`
- 저장 자료 직접 응답은 대부분 `약 0.3초` 안팎
- 자료 부족은 코드로 만들지 않음

디자인 스타일:

- tall vertical technical infographic poster
- off-white paper background
- subtle paper texture
- clean whiteboard explainer style
- black ink sketch lines
- rounded rectangular section cards
- thin arrows connecting steps
- muted green, teal, orange, red, yellow, violet accents
- numbered circular step badges
- simple technical icons
- roomy spacing and large labels
- small callout notes only where useful
- engineering diagram 느낌
- startup technical blog / AI thread 스타일

피해야 할 것:

- 웹페이지 캡처처럼 보이는 결과
- 표준 웹 UI처럼 보이는 결과
- 작은 글씨가 빽빽한 운영 명세표
- 모든 단계마다 긴 설명 박스와 시간 badge를 붙이는 구성
- 세부 API명과 세부 벤치마크 숫자를 본문에 많이 넣는 구성
- 랜덤한 영어/한글 더미 텍스트
- 존재하지 않는 기술명, API명, 수치
- 근거 없는 접근성 정보나 장소명

정확성 제한:

- 검색 설정을 표시한다면 `top_k=40`만 사용해.
- 예비 관광 카드 수를 표시한다면 `904개 Markdown`만 사용해.
- 응답 시간을 표시한다면 `대부분 약 0.3초 안팎`만 크게 사용해.
- 세부 벤치마크 숫자는 이미지에 표시하지 않는 것이 원칙이다.
- LLM 보조는 기본 흐름의 주인공처럼 크게 그리지 말고, 선택적 보조로 작게 다뤄.

가장 중요한 요구사항:

이 이미지는 최신 프로젝트 사실을 바탕으로 하지만, 모든 사실을 한 장에 넣는 문서가 아니다.

정보를 적당히 압축해서, 사람이 3초 안에 “질문 → 검색 → 보강 → 카드 → 평가” 흐름을 이해하고, 10초 안에 핵심 기술 구조까지 파악할 수 있게 만들어줘.

최종 결과는 새로 그린 AI technical infographic image여야 하며, 웹페이지 렌더링 결과처럼 보이면 실패다.
